# What Blitz Strike leaves behind

Blitz Strike ([shinthink/blitzstrike](https://github.com/shinthink/blitzstrike); repository created September 12, 2026, release `v1.0.0` the same day; MIT; TypeScript; 523 stars and 10 forks on November 26, 2026; reviewed at `9d7a6ecb` (`9d7a6ecba034793fd757899de9a6424339fc9470`, November 4, 2026), package version `2.4.200`) is a Model Context Protocol (MCP) server for security testing. An AI coding client (Claude Code, Cursor, Codex, OpenCode, Gemini CLI, Windsurf, Copilot, Cline, Hermes) starts it over stdio and calls its 199 tools. One call, `run_engagement(<url>)`, runs recon, a reflection sweep and a set of fixed injection and misconfiguration checks against a live site. It ships a 130-tool catalog it can install on demand, about 11,900 nuclei templates copied from projectdiscovery/nuclei-templates, payloads from PayloadsAllTheThings, and playbooks from other projects. It is published on npm as `blitzstrike` (306 versions since September 12, 2026; `latest` was `2.4.198` on November 26, 2026, two patch versions behind the repository). The git history has two squashed commits, so earlier states of the code cannot be compared. File references are to the repository at `9d7a6ecb`.

**Fragility** says what it takes to remove a signal: *code* means editing Blitz Strike, *config* means an environment variable or setting, *operator* means a choice made at run time. *Code (model)* marks a string Blitz Strike writes into a tool result for the driving model to send: removing it means editing Blitz Strike, but the model may also change it or not send it.

## Signals on the target side

Requests from Blitz Strike's own code use the runtime's `fetch`. Where the code sets no `User-Agent`, the request carries the runtime's default: `node` under recent Node.js releases (`undici` under older ones), or `Bun/<version>` under Bun. This is inferred from the runtimes, not written in the code. The recon, open redirect, path traversal, CORS, SSTI, SSRF, SQLi, command injection, XSS, CRLF, host header and JWT checks of `run_engagement` all use that default.

## An exposed Blitz Strike console

There is none. Blitz Strike has no web UI, no HTTP API and no network MCP transport; the MCP server only talks over stdio to the client that started it. The repository ships no favicon or logo for a web page (the only image is `.github/assets/banner.webp`). The one listener is the self-hosted callback server above: it answers every request with `oob-ok`, binds all interfaces on a random port and lives only while a blind check runs, so an internet scan would only catch it by chance. Its headers are Node.js defaults (`Content-Length: 6`, `Connection: keep-alive`, `Keep-Alive: timeout=5`, inferred from Node.js, not set in the code). The Shodan row for it matches any page whose body contains `oob-ok`, so treat a hit as a lead only.
