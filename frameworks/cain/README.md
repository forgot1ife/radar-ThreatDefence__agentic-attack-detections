# Cain Detection Rules and IOCs

Part of [Agentic Attack Detections](../../README.md). Shared indicators and feeds live at the repository root; the rules for behaviors that every agentic framework shows are in [`behaviors/`](../../behaviors).

Detection rules, hunting queries and indicators for **Cain** ([cdxiaodong/cain-agent](https://github.com/cdxiaodong/cain-agent), Python package `cain-agent` 0.2.0, reviewed at `2e3f4f1c`), a command line agent that gives a model a shell and points it at one target: `cain-agent run --target <host or URL>` writes `scope.yaml`, then runs recon, test and report stages, each a model session, and checks every finding with a second session that does not share context with the first. It runs on the Claude Agent SDK by default or, with `--backend pi`, on a Node bridge for Anthropic, OpenAI, Google, DeepSeek, GitHub Copilot or OpenRouter models. No vendor or CERT report of Cain in a real intrusion was found on November 26, 2026, so this folder is built from the source code alone: it finds Cain testing you and Cain running on a host. It has no web console to find on the internet.

## Limits

- Cain's requests to targets are the requests of the tools its model runs. The two markers are examples in a skill: the model may use them, change them or skip them, and the skills are only loaded when Cain runs from a clone, not from its Docker image.
- The prompt rules need model requests in clear text (a plain-HTTP `PI_BASE_URL` gateway, an AI gateway or TLS inspection) and UTF-8 bodies.
- A match means Cain, not an attacker: it is published for authorized assessments. Check who ran it and whether the test was agreed.
