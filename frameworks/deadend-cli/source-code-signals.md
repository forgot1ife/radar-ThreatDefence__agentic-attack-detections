# What Deadend CLI leaves behind

Deadend CLI ([straylabs-ai/deadend-cli](https://github.com/straylabs-ai/deadend-cli); `github.com/xoxruns/deadend-cli` redirects there; repository created July 22, 2025; AGPL-3.0; not archived; 338 stars and 55 forks on November 26, 2026; Python backend, TypeScript terminal UI on Bun; reviewed at `34e83717` (`34e8371739d70b24034e2fa47f64350e7f7743d3`), August 7, 2026, the last push) is an autonomous web application penetration testing agent by Yassine Bargach of Stray Labs. Its README reports about 80% on the XBOW validation benchmark with Kimi K2.5. A supervisor agent splits the goal into tasks and hands them to sub-agents: a requester that sends raw HTTP through Playwright, a shell agent that runs commands in a Kali container, a Python agent, a web app analyzer and an authenticator (`deadend_agent/agents/`).

It is distributed three ways: release archives from GitHub (`install.sh`, last tag `v0.1.15`, April 11, 2026), the PyPI package `deadend_cli` (versions 0.1.1, 0.1.4 and 0.1.15 listed on November 26, 2026), and from source with `uv` and `bun`. The Kali sandbox image `xoxruns/sandboxed_kali` is on Docker Hub (registered October 2, 2025, last updated April 12, 2026, 2,737 pulls on November 26, 2026). The code at `34e83717` differs from `v0.1.15` in how test credentials reach the model; both are described below, and `v0.1.15` references are to commit `acb8da6b`.

File references are to `34e83717` unless a tag is named. Paths under `deadend_agent/`, `deadend_prompts/` and `data/` are inside `deadend_cli/` (for example `deadend_cli/deadend_agent/src/deadend_agent/constants.py` is written `deadend_agent/constants.py`).

**Fragility** says what it takes to remove a signal: *code* means editing Deadend CLI, *config* means a setting or environment variable, *operator* means a choice made at run time. *Code (prompt)* marks a string in an agent prompt: removing it means editing Deadend CLI, but the model can also change it on any run, so treat it as likely, not certain.

## An exposed Deadend CLI

There is nothing to expose. The backend is a stdio JSON-RPC process owned by the terminal UI, and the sandbox container publishes no port. The README images under `assets/` are not served by anything, so no favicon hash or page title applies. `exposure/shodan-queries.csv` gets no rows.

## What has been seen in the wild

- No vendor or CERT report of Deadend CLI used in an intrusion was found (searched November 26, 2026).
- The repository commits its own XBOW benchmark logs (`benchmarks-results/xbow/`, January 2026 runs). They are ANSI-coloured terminal transcripts of the agent against local XBOW challenges, and they are the evidence above that the marker and the test account reach targets.

## Not verified, and inferred

- Nothing was run. The placeholders on the wire at `34e83717` are inferred from the templates and the swap code.
- The GitHub releases list could not be read (API rate limit); tags run to `v0.1.15`, and PyPI lists 0.1.15 as the newest version.
- The PyOxidizer release binaries, the Docker image contents beyond the Dockerfile, and the `simple-python-interpreter-sandbox` and `validation-benchmarks-xbow` submodules were not examined. Release binaries were not hashed.
- The clone was made without a checkout; files were read with `git show` and `git grep`. A few blobs could not be fetched from the promisor remote during whole-tree greps; the files cited were all read.
