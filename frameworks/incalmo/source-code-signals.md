# What Incalmo leaves behind

Incalmo ([cylabcyberautonomy/Incalmo](https://github.com/cylabcyberautonomy/Incalmo); the README badges still point at the earlier home `bsinger98/Incalmo`; first commit May 5, 2025; MIT license; 154 stars in the November 2026 exposure pass; no tags or releases; reviewed at `8cd02e0e94889461bd04924c1db5b79cf7dc256c`, November 2, 2026, 246 commits) is the code for the Carnegie Mellon CyLab paper "On the Feasibility of Using LLMs to Execute Multistage Network Attacks" ([arXiv 2501.16466](https://arxiv.org/abs/2501.16466)). A planning model writes Python that calls Incalmo's high-level actions (scan, lateral move, escalate privilege, find information, exfiltrate data). An action layer turns each one into shell commands and runs them on compromised hosts through MITRE Caldera's Sandcat implant, which beacons to Incalmo's own Flask C2 server. A non-LLM mode runs hand-written state-machine strategies through the same layer. Python 3.13, Flask 3.1.0, Werkzeug 3.1.3, Celery 5.5.3 (`uv.lock`), and a React UI. No PyPI package and no published container image: the images are built locally from `docker/`. File references are to the repository at `8cd02e0e`.

**Fragility** says what it takes to remove a signal: *code* means editing Incalmo, *config* means an environment variable or setting, *operator* means a choice made at run time. *Code (prompt)* marks a string that is an example in a model prompt: removing it means editing Incalmo, but the model can also change it on any run, so treat it as likely, not certain.

The implant binary (`incalmo/c2server/agents/sandcat.go`, `incalmo/c2server/payloads/sandcat.go` and `sandcat.go-linux`, one blob `25d11bb2`, 5,984,256 bytes), the Metasploit stager `payloads/bind_metasploit_session` (blob `c3a78a4c`, 198 bytes) and the exploit and helper scripts under `incalmo/c2server/payloads/` were not read. The implant's traffic is described only from Incalmo's own server handlers and from the commands Incalmo builds.

## The C2 protocol (what an implant and the server exchange)

| Signal | What it looks like | Code | Fragility |
|---|---|---|---|
| Beacon request | `POST /beacon`. The body is base64 of a JSON object the server reads `paw`, `results`, `username`, `privilege`, `pid`, `host_ip_addrs` and `host` from. A JSON object encoded with no leading space starts `eyJ` | `incalmo/c2server/routes/agent_routes.py:31-54`, `incalmo/c2server/shared.py:73-75` | Code |
| Beacon answer | Base64 of `json.dumps({"paw": ..., "sleep": 3, "watchdog": 60, "instructions": "[...]"})`, so the body starts `eyJwYXciOiAi` (`{"paw": "`). Flask sends it as `text/html`. Sleep is 3 seconds, 10 after a delete; the server picks an 8-character paw if the implant sends none | `agent_routes.py:41-42,77-92`, `shared.py:78-80` | Code |
| Instruction | Each instruction is `{"id": <uuid4>, "command": base64("./<script>"), "executor": "sh", "payloads": [...], "uploads": [], "sleep": 0, "timeout": 60, "deadman": false, "delete_payload": true}` inside the base64 answer | `incalmo/models/instruction.py:5-14`, `incalmo/c2server/routes/command_routes.py:51-60,98-106` | Code |
