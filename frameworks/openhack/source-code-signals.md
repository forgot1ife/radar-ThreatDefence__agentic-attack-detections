# What OpenHack leaves behind

OpenHack ([openhackai/OpenHack](https://github.com/openhackai/OpenHack); repository created May 2026; 491 stars on November 26, 2026; fork count not retrieved) has shipped two different programs under one name, and both are in this review:

- **v2** (the current `main`, reviewed at `f94e153c` (`f94e153c5e6cc55218692ff6827ca1ac4e17e6a9`), November 23, 2026; release `v2.0.0`; AGPL-3.0-only from this commit, MIT before it). A Bun/TypeScript **source-code** scanner: it reads a local project, sends excerpts to a model and shows findings in a dashboard on `127.0.0.1:6969`. It sends nothing to a target. It is distributed as GitHub release archives through `install.openhack.com` and as the npm package name `@openhack/local` in `package.json` (whether that name is published on npm was not checked).
- **v0.x** (the Python package `openhack` on PyPI, latest `0.2.4`, uploaded August 21, 2026; reviewed at tag `v0.2.4`, `8fdfdddf` (`8fdfdddffa1f493d21e3e6dd98d911e7c531b84b`)). A terminal pentest agent: besides source review it runs commands on the operator's host, drives nmap, sqlmap, nuclei, httpx and subfinder, writes canary rows into a target's database and makes targets call back to an out-of-band collector at `oob.openhack.com`. Its default model provider is the vendor's hosted gateway `api.openhack.com/v1`. The last Python commit on `main` (`6a0675eb`, October 16, 2026) differs from `v0.2.4` only in `config.py`, `setup.py` and `tui.py`. The README at `f94e153c` says the v2 installer does not install earlier releases, but `pip install openhack` still gets 0.2.4.

File references marked **v2** are to `f94e153c`; those marked **v0.2.4** are to `8fdfdddf`.

**Fragility** says what it takes to remove a signal: *code* means editing OpenHack, *config* means an environment variable or setting, *operator* means a choice made at run time. *Code (prompt)* marks a string the system prompt asks for: removing it means editing OpenHack, but the model can also skip it on any run, so treat it as likely, not certain.

## An exposed OpenHack console

There is no internet exposure to look for in normal use. v2 binds `127.0.0.1` with no option to change it, and its `Host` check answers any request addressed by IP or by another name with 403 `{"error":"This dashboard only accepts requests addressed to localhost."}`. v0.2.4 has no web server (only a `localhost:1455` OAuth callback during a ChatGPT login). The vendor's hosted service (`app.openhack.com`) is not an operator console.

## What has been seen in the wild

Public reports of OpenHack used in an intrusion were not searched for this draft. Nothing in this folder comes from an incident.

## What the code does not contain

- v2: no network tool, no exploit code, no listener beyond loopback, no telemetry, no update check.
- v0.2.4: no C2 or implant; the out-of-band collector and the disposable mailbox are vendor services the code calls, not code in the repository.

## Not verified, and inferred

- Nothing was run. Bun's default `User-Agent` on v2 model calls and httpx's on the v0.2.4 update check are library defaults, not checked.
- Whether `oob.openhack.com`, `api.openhack.com` and the `inbox` mailbox service still answer was not checked (no contact with vendor infrastructure). The mailbox domain is set by the vendor's CLI and is not in the repository.
- Whether `@openhack/local` is published on npm, and the repository's fork count, were not checked (GitHub API rate limit).
- Whether the installed `claude` and `codex` CLIs accept every flag OpenHack passes (for example `--safe-mode`, `--restricted`, `--no-daemon`) was not checked; OpenHack tells the user to update the CLI when they are refused (v2 `src/providers/subscription.ts:98`).
- EDR products cut long command lines. The Claude Code child's system prompt is several kilobytes, so `source-review worker inside OpenHack` may be cut off; the `--settings` JSON near the start is the safer anchor.
