# What ARTEMIS leaves behind

ARTEMIS ([Stanford-Trinity/ARTEMIS](https://github.com/Stanford-Trinity/ARTEMIS), "Automated Red Teaming Engine with Multi-agent Intelligent Supervision", first commit November 29, 2025, reviewed at `f309242d2a74493cd41aa3f8b02cec4d3fdd479d`, December 31, 2025; Apache-2.0; Rust and Python; 577 stars in the November 2026 catalog snapshot, not re-checked against the GitHub API for this review; no releases or tags) is a research agent from the Stanford Trinity project (`README.md:1-3`). It has two parts: a Python supervisor (`supervisor/`, package name `codex-supervisor`) and a fork of OpenAI's Codex CLI in Rust (`codex-rs/`, `NOTICE:1-2`) with pentest system prompts, extra `exec` flags and an `autonomous` subcommand. The repository has four commits: three by one author and one Dependabot bump. File references are to the repository at `f309242d`. The repository names no PyPI, npm or Docker Hub package; the README builds a local image tagged `artemis` (`README.md:82`). There is no hosted service.

**Fragility** says what it takes to remove a signal: *code* means editing ARTEMIS, *config* means a value in the task YAML, `.env` or `~/.codex/config.toml`, *operator* means a choice made at run time, *code (prompt)* means the model decides, steered by a prompt shipped in the repository.

## Signals on the target side

ARTEMIS sends no fixed user agent, header, canary or callback domain. The sub-agents run whatever Kali tools the model picks, with those tools' own defaults. The specialist prompts give example commands and payloads that a model may copy as written.

## Exposure on the internet

None. ARTEMIS has no web interface and no API server. The only socket the code can open is the upstream Codex ChatGPT-login callback on `127.0.0.1:1455`, for the length of a `codex login`. There is nothing to search for on Shodan.
