# Offensive prompt packs for coding agents

Some offensive "AI pentest" projects ship no agent of their own. They ship instructions that turn a general coding agent (Claude Code, Codex, Trae, Qoder) into an attack tool: skill files, subagent definitions or a system prompt. The agent then runs the attack tools itself, so on a target their traffic looks like that coding agent and the tools it starts. That traffic is already covered by the shared rules for coding agents that run attack tools and for model API calls from servers. What these packs add that can be detected is their files on the host where they are installed.

| Pack | What it installs | Where | Rules |
|---|---|---|---|
| [SnailSploit/Claude-Red](https://github.com/SnailSploit/Claude-Red) at `6196ba74` | 79 skill files named `offensive-<topic>` (SQL injection to EDR evasion, shellcode and C2) | `~/.claude/skills/claude-red/` by default, or any skills folder | YARA `ClaudeRed_*`, Sigma `file_event_claude_red_offensive_skills` |
| [0xSteph/pentest-ai-agents](https://github.com/0xSteph/pentest-ai-agents) at `e5d7aa02` (3.4.0) | 52 Claude Code subagents, 3 slash commands, a findings database | `~/.claude/agents/`, `~/.claude/commands/`, `~/.pentest-ai/bin/`, `~/.pentest-ai/findings.db` | YARA `PentestAIAgents_*`, Sigma `file_event_pentest_ai_agents_subagents` |
| [chAng-L19/codex-redteam-mode](https://github.com/chAng-L19/codex-redteam-mode) at `cd8db548` (2.1.0) | Jailbreak prompts loaded into Codex's system layer through `model_instructions_file`, hooks, an MCP server and an optional local prompt rewrite proxy | `~/.codex/prompts/Jailbreak.*.md`, `~/.codex/redteam-mode/`, `~/.codex/hooks/`, `~/.agents/skills/redteam-boundary-policy/`, edits to `config.toml`, `AGENTS.md` and `hooks.json` | YARA `CodexRedteamMode_*`, Sigma `file_event_codex_redteam_mode_install` |
| [ok-helloworld/vibe-pentest](https://github.com/ok-helloworld/vibe-pentest) at `0b80fbf1` (1.0.32) | A skill that runs parallel web testing sub-agents, with helper scripts and reports | a `vibe-pentest` folder under the agent's skills folder; sub-agents in `<project>/.<agent>/agents/` | YARA `VibePentest_Skill_Files`, Sigma `file_event_vibe_pentest_skill` |

The YARA rules are in [`yara/prompt-packs.yar`](yara/prompt-packs.yar): scan home folders, project folders and container layers. The Sigma rules are in [`sigma/file_event/`](sigma/file_event). Their file names and strings are in `iocs/indicators.csv`.

There is little else to detect. The packs have no listener, no web console and no infrastructure of their own, so there is nothing to find on the internet and no addresses to block. Their text tells the agent which tools to run but does not fix a user agent or a marker in the requests, so there is no Suricata rule. Two packs carry helper code beyond the prompts: vibe-pentest's Python scripts send the user agent `vibe-pentest-deserialization-payload/1.0` when they download ysoserial, and codex-redteam-mode runs a local MCP server and a prompt rewrite proxy on `127.0.0.1:8765`. Neither is reachable from outside the host. Each rule only means that a pack is installed. A security team may have installed it on purpose, so check who owns the host before you act. codex-redteam-mode is the exception: its purpose is to remove the model's safety behaviour, so it is worth a look on any host.

This folder groups four projects that offensive.agency lists as agents but that contain no agent code. It has no Suricata rules, no hunts and no exposure searches, for the reasons above.
