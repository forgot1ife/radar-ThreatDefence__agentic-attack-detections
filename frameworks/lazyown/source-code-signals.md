# What LazyOwn leaves behind

LazyOwn ([grisuno/LazyOwn](https://github.com/grisuno/LazyOwn); AGPL-3.0, version 0.5.0 in `version.json` and `pyproject.toml`; about 303 stars in an earlier scouting pass at `468fa8a`, not re-read for this review because the GitHub API was rate limited; reviewed at `f4e54de958740c421071ac20c98eff1bd6ab7957`, November 25, 2026) is a Python red team framework. It has a `cmd2` shell with several hundred attack commands (`lazyown.py`, `cli/commands/`), a multi-operator C2 server with a web dashboard (`lazyc2.py`, the `lazyc2/` package and `templates/`), HTTP and DNS beacon channels, phishing and short-URL tracking, and an MCP server (`skills/lazyown_mcp.py`) through which Claude Code, Hermes Agent or OpenCode drive the whole framework. The repository is large (4,541 files). This review covers the C2 server, the beacon protocol as the server's handlers see it, the MCP control path and the listeners. The implant, payload, loader, BOF and shellcode folders (`sessions/implant/`, `sessions/win/`, `sessions/lin/`, `exploits/`, `bofs/`, `modules/backdoor/`, `modules/c2_builder.py` and the like) were not read. File references are to the repository at `f4e54de9`.

**Fragility** says what it takes to remove a signal: *code* means editing LazyOwn, *config* means a key in `payload.json` or an argument, *operator* means a choice made at run time.

## What the code does not contain

- No telemetry to the author and no update check in the C2 server or the MCP server.
- The C2 has no default password that survives start-up: weak or `CHANGE_ME` credentials are replaced and printed. The MCP server falls back to `LazyOwn`/`LazyOwn` only for its own requests if neither the environment nor `payload.json` give credentials.
- The C2 never binds `0.0.0.0` unless `allow_unspecified_bind` is set; in the shipped Docker setup (`LHOST=0.0.0.0`) it therefore falls back to `127.0.0.1` inside the container (inferred from the code; not run).

## Not verified, and inferred

- Nothing was run. Server headers, the Flask JSON formatting (sorted keys, compact separators in Flask 3.1) and the exact 401 answer are read from the code and the pinned library versions.
- Beacon user agents, headers other than `X-Signature` and `Authorization: Bearer` on staging, and the main Go beacon's timing were not read from implant code. The Gmail-style route, the user agent strings and the 6-second sleep are what the C2 configures and serves; whether every implant build uses them was not checked.
- `/upload` is registered as `<route>/upload`, which gives a double slash (`/gmail/v1/users//upload`); how clients reach it was not checked.
- The MCP tools post JSON to `/issue_command`, which reads form fields, and call `/get_connected_clients`, which needs a session login rather than Basic auth, so those MCP calls may fail at this commit. The paths are still what the traffic shows.
- Repository creation date, fork count and the current star count were not read (GitHub API rate limit). Whether `ghcr.io/grisuno/lazyown` is published was not checked beyond the README badge.
- The Shodan favicon hash is computed from the repository file; it was not checked against Shodan or against other projects using the same icon.
- Public reports of LazyOwn used in intrusions were not searched for this draft.
