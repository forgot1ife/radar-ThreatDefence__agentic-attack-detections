# What RAPTOR leaves behind

RAPTOR ([gadievron/raptor](https://github.com/gadievron/raptor); "Recursive Autonomous Penetration Testing and Observation Robot"; repository created October 17, 2025; MIT per `pyproject.toml` and the README, shown by GitHub as `NOASSERTION` because of the third-party notices; 4,064 stars and 618 forks on November 26, 2026; not archived; latest release `v3.1.0`, September 7, 2026; reviewed at `ac734352` (`ac734352c8d00c40678ff74b58d18cff4e8a37a1`), November 25, 2026) is a security research framework written mostly in Python that runs as a Claude Code session. Its slash commands chain Semgrep, CodeQL, Coccinelle, Joern, Ghidra, AFL++ fuzzing, Frida, a web scanner, software composition analysis, LLM-based exploitability validation and the generation of proof-of-concept exploits and patches against a codebase, a binary or a web application. File references are to the repository at `ac734352`.

**Fragility** says what it takes to remove a signal: *code* means editing RAPTOR, *config* means an environment variable or setting, *operator* means a choice made at run time. *Code (prompt)* marks a string in a slash command or skill file that the model reads, so the model can change it on any run.

## Signals on the target side

Only the web workflow (`/web`, `python3 raptor.py web --url <url>`) touches a remote system. The source, binary, fuzzing and validation workflows run on the operator's machine against local code, binaries and builds. The web scanner has an approval level (`--approval-level passive|active|intrusive`, default `active`) and records the authorised origin in `scope-receipt.json`.

## An exposed RAPTOR console

There is none. RAPTOR is a command line tool around a Claude Code session. Its LLM dispatcher listens on Unix sockets, the SAGE sidecars bind to loopback, and the opt-in callback listener answers `ok` with Python's stock `Server: BaseHTTP/0.6 Python/3.x` header (inferred from the standard library), which cannot be told apart from other Python servers. No exposure query is proposed.

## What the code does not contain

No implant, C2 channel, persistence or anything that runs on a victim host. RAPTOR writes proof-of-concept exploits for the code it analyses and runs them in its sandbox against local builds; the web workflow is the only one that sends traffic to a remote target, and it is scoped to one origin recorded in `scope-receipt.json`. No telemetry. Results stay in the checkout's `out/` folder or the project folder.

## Not verified, and inferred

- Nothing was run. Command lines, headers and file contents are read from the code.
- The exploit and patch files, sample exploits and test corpora in the repository were not opened; only their names and output paths were recorded.
- Whether Playwright's Chromium sends a `HeadlessChrome` user agent during RAPTOR's crawl and XSS proof was not checked: the code sets no user agent for the browser.
- How `requests` encodes the login checks (form body) is read from the client wrapper's use of `data=`; JSON login forms may send the same values in JSON.
- No vendor or CERT report of RAPTOR used in an intrusion was searched for in this pass.
