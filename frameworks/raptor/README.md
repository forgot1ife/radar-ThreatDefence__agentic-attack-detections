# RAPTOR Detection Rules and IOCs

Part of [Agentic Attack Detections](../../README.md). Shared indicators and feeds live at the repository root; the rules for behaviors that every agentic framework shows are in [`behaviors/`](../../behaviors).

Detection rules, hunting queries and indicators for **RAPTOR** ([gadievron/raptor](https://github.com/gadievron/raptor), reviewed at `ac734352`, November 25, 2026, after v3.1.0), an open-source security research framework that runs as a Claude Code session. Its slash commands chain static and binary analysis, fuzzing, a web scanner, LLM-based exploitability validation and the writing of proof-of-concept exploits and patches. No vendor or CERT report of RAPTOR in a real intrusion is known to this project, so this folder is built from the source code alone: it finds RAPTOR's web scanner testing your sites and RAPTOR running on a host. It has no web console to find on the internet.

## Limits

- Only the web workflow sends traffic to a remote target. Source review, binary analysis, fuzzing and exploit generation run on the operator's machine, so the host rules are the only way to see them.
- The scanner's browser, ffuf and nuclei send their own user agents; injection payloads are generated by the model and are not fixed.
- RAPTOR is published for security research and its scanner announces "Authorized Testing". A match means someone ran RAPTOR, not that it was malicious: check who ran it and whether the test was agreed.
