# What CHYing-agent leaves behind

CHYing-agent ([yhy0/CHYing-agent](https://github.com/yhy0/CHYing-agent); repository created November 10, 2025; MIT; 596 stars and 54 forks on November 26, 2026; not archived; reviewed at `0d2ee81f`, April 25, 2026, the latest commit) is a Python contest agent written for the Tencent Cloud hackathon "intelligent penetration challenge" (TCH). An orchestrator built on the Claude Agent SDK (`claude-agent-sdk`, which drives a Claude Code CLI) hands work to sub-agents: an executor that runs commands in a Kali container, a browser agent on Chrome DevTools MCP, a reverse-engineering agent on a Ghidra MCP server, and an optional post-exploitation agent on Metasploit. It ships a Markdown knowledge base, Claude Code skills, a FastAPI and Vue dashboard, and contest runners for the Tencent and HTB platforms. The README says the author ran it with GLM-5 through Tencent Cloud's Anthropic-compatible endpoint and also on a modified Claude Code CLI build. There is no PyPI or npm package, no published Docker image and no hosted service: the operator builds the image `chying-agent-docker-tools:latest` locally. File references are to the repository at `0d2ee81f`.

**Fragility** says what it takes to remove a signal: *code* means editing CHYing-agent, *config* means an environment variable or setting, *operator* means a choice made at run time. *Code (prompt)* marks a string that is an example in a prompt or skill: removing it means editing CHYing-agent, but the model can also change it on any run, so treat it as likely, not certain.

The release is partial. `main.py` imports `chying_agent.multi_target_manager` and `chying_agent.ctf_platform`, which are not in the repository, so the `--ctf`, `--web`/`--pwn`/... and `--platform` modes fail as published. The single-target mode (`-t`), the dashboard (`--dashboard`) and the contest runners are complete.

## Signals in model traffic

Where model traffic is inspected, CHYing-agent requests go to an Anthropic-compatible `/v1/messages` endpoint with the Claude Code system prompt plus the orchestrator identity `You are CHYing Orchestrator - an autonomous security automation system for CTF, penetration testing, and red team operations.` (`chying_agent/prompts/orchestrator_identity.md:2`), and tool definitions named `mcp__chying__exec`, `mcp__chying__record_key_finding`, `mcp__chying__wss_connect`, `mcp__chying__wss_close`, `mcp__chying__submit_flag`, `mcp__chying__view_hint` (`chying_agent/claude_sdk/mcp_tools.py:1244,1352-1354`). The C2 sub-agent prompt starts `You are a post-exploitation and C2 operations specialist.` (`chying_agent/prompts/c2.md:2`).

## What has been seen in the wild

- No vendor or CERT report of CHYing-agent used in an intrusion was found.
- The README describes its use in the second Tencent Cloud hackathon (main arena rank 60, first place in the parallel "Null Zone" arena) and links the contest's public leaderboard. These are contest results, not abuse.
- No public detection rules for CHYing-agent were found.

## What the code does not contain

No implant, webshell manager or persistence code. Post-exploitation uses the stock Metasploit in the Kali container (msfvenom payloads, meterpreter, reverse shells), driven through tmux by the model, and the prompt tells the C2 agent not to deploy persistence unless the orchestrator asks. The example Sliver C2 MCP entry in `mcp.json.example` points at a server the operator would run; no Sliver code is shipped. No telemetry goes to the author. Scope is held by the prompt only: there is no allow list of authorized targets.

## Not verified, and inferred

- Nothing was run. The WebSocket and HTTP user agents, the `server: uvicorn` header, the exact process command lines of the Claude Code CLI child and Docker exec processes are read from the code or inferred from library defaults.
- The web terminal markers were not checked against a live ttyd, wetty, GoTTY or Kubernetes terminal. GoTTY sends output base64-encoded, so the markers are not visible in cleartext in its frames; client frames are masked, so the typed command is not visible on the wire either. The markers are visible in ttyd, wetty, Kubernetes and plain WebSocket terminal output, and in the target shell's history.
