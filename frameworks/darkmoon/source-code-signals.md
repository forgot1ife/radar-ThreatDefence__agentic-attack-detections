# What DarkMoon leaves behind

DarkMoon ([ASCIT31/Dark-Moon](https://github.com/ASCIT31/Dark-Moon), made by ASC IT, repository created November 26, 2024, reviewed at `bb1b70ce`, November 22, 2026, release v1.7.0) is an autonomous AI penetration testing stack. A branded fork of the OpenCode coding agent runs an orchestrator prompt and about 50 specialist sub-agents (web, CMS, cloud, Active Directory, Kubernetes, CI/CD, email, firmware, LLM endpoints). The agents never run a command themselves: every command goes through the DarkMoon MCP server, which runs it with `docker exec` in a separate toolbox container. The repository had 1,306 stars and 230 forks on November 26, 2026. It was GPL-3.0 up to `edfe9cb` (October 27, 2026) and is AGPL-3.0 from v1.7.0 (`LICENSING.md`). A paid Pro edition adds a web dashboard and REST API; it is not in this repository. File references are to the repository at `bb1b70cef54c01344e90b373d48bd9a7f91e5dfe`.

**Fragility** says what it takes to remove a signal: *code* means editing DarkMoon, *code (prompt)* means editing an agent's Markdown prompt (or the model choosing differently, since the prompt only shows the command), *config* means an environment variable or a Compose setting, *operator* means a choice the operator makes when running it.

## Signals on the target side

Most of what DarkMoon sends to a target is its toolbox with default settings (naabu, httpx, nuclei, katana, ffuf, sqlmap, wpscan, netexec), and no source file sets a user agent for them. The strings below come from commands written out in the agent prompts. The model usually copies those commands, but it may change them, so treat each as a strong lead when it appears and expect nothing when it does not.

## Exposure

The open-source edition has no web console. Its documentation says so (`docs/full.md:2044`, "no web dashboard, no REST API"). It serves only the MCP endpoint, on `127.0.0.1:8181` inside the `opencode` container, which Compose does not publish. An MCP server reachable from outside means the operator changed `DARKMOON_MCP_HOST` and published the port. It has no authentication, and its `execute_command` tool runs commands as root in the toolbox container, which has the host's Docker socket. Internet scanners that do not speak MCP will not see the server name, so the Shodan rows for it are low yield.

The paid Pro edition has a web dashboard and a REST API (the n8n guide gives `http://darkmoon.internal:8000` as an example base URL, `docs/n8n-integration.md:30-31`) and a demo at `demo.dark-moon.org`. Its code is not public, so its page title, icon and headers could not be checked. The logo files in the repository (`docs/pics/logo_blue.png` mmh3 `2084406225`, md5 `ea86f88883314e5098249e1d70609300`; `logo_black.png` mmh3 `-1715329125`; `logo_white.png` mmh3 `-189600147`) are README images, not a favicon any DarkMoon code serves; they are recorded only so a Pro dashboard that reuses one can be recognized.

## What has been seen in the wild

No public report of DarkMoon used in an intrusion was found. Its only published assessments are the vendor's own (OWASP Juice Shop, DVGA, DVWA).

## What the code does not contain

DarkMoon ships no implant, C2 or persistence of its own. It reports to nobody: there is no telemetry, update check or callback host. The toolbox does not install `interactsh-client` (it is only named in the list of tools whose update check is turned off, `conf/pd-disable-update-check.sh:18`), and no agent prompt names an out-of-band (OAST) domain.
