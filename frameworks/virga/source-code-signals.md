# What Virga leaves behind

Virga ([r74tech/virga](https://github.com/r74tech/virga); repository created December 10, 2025; MIT; 11 stars and 4 forks on November 26, 2026; default branch `develop`; no releases, tags or container images; reviewed at `43773ffe` (`43773ffea07dc2381cd6730de5521fbf4ceca069`), November 23, 2026) is an experimental command and control framework written in Go. Its server takes beacons over HTTP or HTTPS, an operator CLI and a React web UI drive it through an admin REST API, and two MCP servers let an MCP client (the docs show Claude Desktop) run commands on beacons. The beacon can carry a local language model (llama.cpp through the author's `r74tech/llama.go` bindings, by default Qwen3-4B in GGUF format) and run an autonomous loop on the compromised host: the model writes `[EXECUTE: <command>]`, the beacon runs it and feeds the output back. File references are to the repository at `43773ffe`.

This review read the server, the operator CLI and generator, the shared protocol and crypto code, the configs, the web UI and the docs. The implant source (`internal/implant/`) was not read; what the beacon sends is taken from the server's listener handler, the shared protocol structs, the generator that builds the beacon and the shipped `configs/beacon.yaml`. The repository contains no binaries or model files: the model is downloaded at build time (`scripts/download-llama-model.go`).

**Fragility** says what it takes to remove a signal: *code* means editing Virga, *config* means a setting in `configs/server.yaml` or `configs/beacon.yaml`, *operator* means a choice made at run time.

What a scanner sees depends on the bind addresses. The shipped `server.yaml` keeps the admin API and the listener on `127.0.0.1` but puts both MCP servers on every interface, and the Vite config puts the web UI on every interface. The quick-start guide and the built-in defaults bind the admin API and listener to `0.0.0.0` too, and `make update-ip` rewrites `server.host` (and, with `-update-listeners`, the listener bind addresses) to an interface address of the operator's choice (`scripts/update-ip.go:24,181-183,260-264`). An exposed admin API or MCP server gives anyone who finds it full control of every beacon: command execution, file upload and download, port forwarding, extension upload and the killswitch.

## Signals in model traffic

None on the network: the model runs inside the beacon on the compromised host. The beacon's autonomous loop runs commands it reads from the model's text in the form `[EXECUTE: <command>]`, and `beacon.yaml`'s task prompts start `=== TASK: System Reconnaissance ===`, `=== TASK: Network Discovery ===`, `=== TASK: User Activity Analysis ===` and `=== TASK: Persistence Mechanism Analysis ===` and end with `[TASK_COMPLETE]` (`configs/beacon.yaml:69-153`, `docs/usage/ai-features.md`). The generator passes these prompts to the build Base64-encoded in `-X ...BuildLlamaTaskPrompts=` (`internal/cli/generator/binary.go:648-656`), so they are not plain text in the beacon unless the implant also carries them itself (not checked). The MCP path is different: an MCP client such as Claude Desktop sends the operator's requests and the tool results to its own model provider.

## What has been seen in the wild

## Not verified, and inferred

- Nothing was run. The implant source was not read, so the beacon's own headers, its content type, whether it carries the default AES key and how it unpacks the model on the victim are not confirmed. The beacon user agent comes from the generator and the configs.
- The MCP wire format (the SSE endpoint event, Streamable HTTP session headers) comes from the go-mcp library, which was not reviewed.
- Go's default headers (`Content-Type` sniffing on the decoy page, `http.Error` headers) and gorilla/mux's `405` are inferred from those libraries' behavior.
- The beacon size with the model is inferred from the public size of `Qwen3-4B-Q4_K_M.gguf`, not measured.
- `go.mod` lists go-ethereum, gnark-crypto and other blockchain modules as indirect dependencies; why they are there was not investigated.
