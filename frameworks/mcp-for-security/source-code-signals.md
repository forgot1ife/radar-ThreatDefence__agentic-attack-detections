# What MCP for Security leaves behind

MCP for Security ([cyproxio/mcp-for-security](https://github.com/cyproxio/mcp-for-security); MIT, copyright 2025 Cyprox; TypeScript; reviewed at `51dd537f` (`51dd537f5829470ebe508afd33186bd1a0459256`), March 30, 2026, the last commit, "deprecate: migrate to Bolt"; 71 commits) is a set of 23 independent Node.js MCP servers, one folder per tool. Each is a few hundred lines of TypeScript on `@modelcontextprotocol/sdk` that registers one or a few tools, spawns the wrapped program with `child_process.spawn` or `node-pty`, and returns its output. The README now says the repository is no longer maintained and that the tools moved to Bolt (`cyberstrikeus/bolt`, not reviewed). Repository counters (stars, forks, creation date, archive flag) could not be read for this review; an earlier pass recorded 632 stars. File references are to the repository at `51dd537f`.

Folders: `alterx-mcp`, `amass-mcp`, `arjun-mcp`, `assetfinder-mcp`, `cero` (the README links `cero-mcp`), `commix-mcp`, `crtsh-mcp`, `ffuf-mcp`, `gowitness-mcp`, `http-headers-security-mcp`, `httpx-mcp`, `katana-mcp`, `masscan-mcp`, `mobsf-mcp`, `nmap-mcp`, `nuclei-mcp`, `scoutsuite-mcp`, `shuffledns-mcp`, `smuggler-mcp`, `sqlmap-mcp`, `sslscan-mcp`, `waybackurls-mcp`, `wpscan-mcp`. The npm package names in each `package.json` equal the folder names (version 1.0.0, none published by this repository). Compiled `build/index.js` files are committed for 20 of them. There are no images, binaries or payloads; the only non-text file is a stray `.DS_Store`.

**Fragility** says what it takes to remove a signal: *code* means editing a wrapper, *config* means the MCP host configuration, *operator* means a choice made at run time, *code (prompt)* means a tool description the model sees.

## How it runs

| Part | What it does | Code |
|---|---|---|
| Wrapper start | The MCP host starts `node <dir>/<folder>/build/index.js <args>`. The arguments are the path or name of the wrapped program: `which nmap` etc. from `build.sh`, or a bare name in the READMEs (`nmap`, `sqlmap`, `wpscan`, `waybackurls`, `sslscan`). Special cases: commix and smuggler take `<python3 path> <script path>`, shuffledns takes `<shuffledns> <massdns>`, MobSF takes `<MobSF base URL> <API key>`, crt.sh and the header check take none | `nmap-mcp/build.sh:10,16-19`, `nmap-mcp/readme.md:52-54`, `commix-mcp/src/index.ts:6-10`, `shuffledns-mcp/src/index.ts:8`, `mobsf-mcp/src/index.ts:7-15`, `mobsf-mcp/readme.md:53-57` |
| Transport | `new StdioServerTransport()` in every server; no HTTP, SSE or socket listener anywhere | e.g. `nmap-mcp/src/index.ts:172`, `gowitness-mcp/src/index.ts:449` |
| Start-up line | Each writes `<name> MCP Server running on stdio` to stderr (the MCP host's server log): `nmap`, `AMASS`, `Masscan`, `Enhanced gowitness`, `http-headers-security`, and so on. No `EXPOSE`, no compose file | `Dockerfile:1-53` |
| Image | Pushed by a manual workflow as `cyprox/mcp-for-security:<tag>` (Docker Hub user `cyprox`), with a GitHub release per tag | `.github/workflows/docker.yml:19-34` |
| Model providers, telemetry, updates | None. ## Exposure

None. No server listens on a port, the image exposes none, and there is no web page, favicon or health route. `exposure/shodan-queries.csv` gets no rows.
