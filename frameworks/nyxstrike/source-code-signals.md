# What NyxStrike leaves behind

NyxStrike ([CommonHuman-Lab/nyxstrike](https://github.com/CommonHuman-Lab/nyxstrike); repository created February 11, 2026; AGPL-3.0 with a commercial licence offered, copyright CommonHuman-Lab 2026 and 0x4m4 2025; 159 stars and 37 forks on November 26, 2026; not archived; Python and TypeScript; reviewed at `3ac74499b8d77785d1b496791a4aab32a253a9cb`, release 1.9.0, August 20, 2026) is a derivative of HexStrike AI. Its history starts with HexStrike's commits of July 2025, it was published as "HexStrike AI - Community Edition" with `hexstrike_server.py` until April 10, 2026 (commit `148c54b`, released in 1.4.0), and then renamed. Like HexStrike it is a Flask server that wraps offensive tools behind an HTTP API and an MCP client that lets any AI assistant call them. It adds a React dashboard served by the same server, a "decision engine" that profiles a target and ranks tools, its own LLM agents (Ollama by default, or OpenAI or Anthropic), a payload workbench, session notes, findings, loot and credential stores, and a hash-chained run history. The branch `beta/next` (`e39eb41`, November 6, 2026, version 2.0.0) adds macOS installation and changes none of the signals below. No Docker image is published and there is no PyPI package for NyxStrike itself. File references are to the repository at `3ac7449` unless another repository is named.

**Fragility** says what it takes to remove a signal: *code* means editing NyxStrike or one of its CommonHuman-Lab packages, *config* means an environment variable, argument or setting, *operator* means a choice made at run time. *Code (prompt)* marks a string the model is told to use.

## What it shares with HexStrike, and what changed

Rules in [`../hexstrike/`](../hexstrike) that also fire on NyxStrike, so this folder does not repeat them:

| HexStrike rule | Why it fires on NyxStrike |
|---|---|
| Suricata 3803003, Sigma `web_hexstrike_user_agent_or_xss_probe` (UA part) | The exploit generator still writes `"User-Agent": "Mozilla/5.0 (Compatible Exploit)"` (`backend/server_core/generators/ai_exploit_generator.py:92`) |
| YARA `HexStrike_Generated_Exploit` | The same generator template with `def exploit_rce(target_url, command)`; matches `ai_exploit_generator.py` itself and the scripts it writes |
| Suricata 3803011, Sigma `proxy_hexstrike_tool_api` (`/api/tools/` part), hunt 04 | NyxStrike keeps `POST /api/tools/<tool>` on port 8888 (152 tool routes, most with HexStrike's names) |
| Hunt 03, `Python listening on 8888` | Same default port |
| Indicator rows `/tmp/pacu_commands.txt`, `/tmp/prowler_output`, `/tmp/scout-suite`, port 8888 | Same paths (`backend/server_core/tool_specs/cloud_exploit.py:38`, `cloud_audit.py:72,89`) |

HexStrike rules that do **not** fire on NyxStrike, because the strings were renamed or removed: the user agents `HexStrike-HTTP-Framework/` and `HexStrike-BrowserAgent/` (now `Security-HTTP-Framework/` and `Security-BrowserAgent/`), the probe `<hexstrikeXSSTest123>` (now `<xssTest123>`), the health message `HexStrike AI Tools API Server is operational` (now `NyxStrike Tools API Server is operational`), `/api/command` (removed; the shell is `/api/process/execute-async`), the script names `hexstrike_server.py` and `hexstrike_mcp.py`, the files `/tmp/hexstrike_*` and `hexstrike.log`, and the `sh -c which` burst (NyxStrike runs `which` without a shell). NyxStrike installs from before April 10, 2026 still carry the HexStrike names and match the HexStrike rules.

## An exposed NyxStrike server

The dashboard and the API are the same Flask server on the same port, so an exposed NyxStrike is an exposed tool API. What a scanner sees depends on the token:

- **No token** (a loopback install published through a reverse proxy, or releases 1.4.0 to 1.7.0 bound to a public address): `GET /` returns the dashboard page, `/health` and `/web-dashboard` return the tool inventory, and `POST /api/process/execute-async` or any `/api/tools/<tool>` runs commands on the host. That is remote code execution for anyone who finds it, as with HexStrike.
- **Token set** (required since 1.8.0 for a public address): every path, including `/`, returns `401` with Werkzeug's default page. The dashboard cannot load in a browser in that state, because the page itself is behind the bearer check, so operators who want the dashboard put a proxy in front that adds the header, or run without a token behind a proxy.

## Signals in model traffic

Where model traffic is inspected, NyxStrike's own LLM features send system prompts that start `You are NyxStrike, an expert penetration testing analyst.`, `You are NyxStrike, an expert penetration testing planner.`, `You are NyxStrike, an autonomous penetration testing AI assistant embedded in Burp Suite.` and the chat prompt `You are NyxStrike, an expert penetration testing AI assistant embedded in a security operations platform.` (`backend/server_core/llm_agent.py:88,574`, `backend/server_api/burp_agent/routes.py:96`, `config.py:63-67`). With Ollama this traffic stays on the host. An assistant using the MCP client carries NyxStrike's tool definitions, for example `mcp__nyxstrike__nmap_scan`, `mcp__nyxstrike__stingxss_scan` or, in compact mode, `classify_task` and `run_tool`. The agent prompts in `AI/agents/` (`You are the Bug Bounty Leader. You orchestrate a full autonomous bug bounty engagement using NyxStrike MCP tools.`, `You are the HTB CTF Leader. ...`) are meant for an MCP client such as OpenCode.

## What has been seen in the wild

- No vendor or CERT report of NyxStrike used in an intrusion was found (searched November 26, 2026).
- offensive.agency lists one exposed host, as above.
- HexStrike, its parent, was discussed by criminals for NetScaler exploitation and seen by GTIG and Mandiant in intrusions; see [`../hexstrike/`](../hexstrike).

## What the code does not contain

NyxStrike ships no implant, C2 listener or persistence code of its own. It does drive Metasploit (`msfconsole -q -r <data dir>/tmp/mcp_msf_resource.rc` with `exploit -j`), Impacket remote execution, and VaultRip, which harvests credentials from files, process memory, browsers, keyrings and Kerberos caches on a host it runs on. Results stay on the operator's disk; there is no telemetry. There is no scope list or target block: any target typed by the operator or chosen by the assistant is tested.
