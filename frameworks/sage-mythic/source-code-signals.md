# What Sage leaves behind

Sage ([MythicAgents/sage](https://github.com/MythicAgents/sage); repository created April 3, 2025; GPL-3.0; 53 stars and 7 forks on November 26, 2026; releases v0.1.0-alpha (January 2026) to v0.4.0 (November 24, 2026); reviewed at `cbff42f0abc54d3c64b40d3a71cffce01a057023`, November 23, 2026, which declares version 0.4.0) is an AI operator that runs inside the Mythic C2 framework. It installs into a Mythic server as a chat container (`mythic-cli install github https://github.com/MythicAgents/sage`), reads the operation's callbacks, tasks, credentials and files through Mythic's API, reasons over a BloodHound CE graph through the BloodHound MCP server, and proposes the next step as a Mythic task. In supervised mode each guarded task runs only after the operator accepts an approval card; an experimental auto mode works an objective without per-action approval. Sage itself opens no connection to a target: everything that reaches a target is a task executed by a Mythic payload callback (Apollo is the only one the project has qualified). Python 3.14, LangChain and LangGraph, the `mythic` scripting library and `mythic-container` SDK, and an embedded Arize Phoenix trace server. File references are to the repository at `cbff42f0`.

**Fragility** says what it takes to remove a signal: *code* means editing Sage, *config* means an environment variable, chat configuration or Mythic setting, *operator* means a choice made at run time (for example a value the operator or model passes as a task parameter, which replaces the default). *Code (prompt)* marks text from a model prompt.

Mythic itself, its payload types (Apollo and the others) and the BloodHound MCP server were not cloned or read. The RabbitMQ exchange and queue names a chat container uses are defined by the `mythic-container` SDK (pinned at `0.7.0rc9`), not by this repository, so they are not listed here. The C2 traffic between Mythic and its payloads is the payload type's own and is not covered.
