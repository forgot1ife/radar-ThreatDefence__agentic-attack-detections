# What BreachWeave leaves behind

BreachWeave ([m-sec-org/BreachWeave](https://github.com/m-sec-org/BreachWeave); repository created April 22, 2026; Apache-2.0; 775 stars and 153 forks on November 26, 2026; default branch `main`; no releases, tags or published container images; languages TypeScript, with Python, shell and payload files in the skill folders) is a multi-agent penetration testing platform written in TypeScript for Bun on the pi-mono agent SDK (`@mariozechner/pi-agent-core`, `pi-ai`, `pi-coding-agent` 0.65). The repository description reads, in Chinese, "intelligent pentest agent with a Manager/Observer/Solver multi-role architecture, based on the pi-mono SDK". The README lists first place (1 of 613) in the online round and first prize in the offline final of the second Tencent Cloud Hackathon intelligent penetration challenge in April 2026.

Two branches matter. `main`, reviewed at `bc2d9502` (`bc2d9502a2625c5ef354adc30243bd091341cc51`, October 9, 2026), is the CTF build: package name `tch-agent`, page title `tch-agent`, a client for the contest platform API, and **no authentication on the web console**. `pentest`, reviewed at `6957a55f` (`6957a55f15e0d585f4b728c831021a34f7e02891`, October 9, 2026), is described as the build for authorized penetration tests: product name BreachWeave, local projects and assets instead of the contest API, report submission per asset, and JWT login with open self-registration. File references are to `main` at `bc2d9502` unless marked `pentest:`. A third branch, `feature/taric`, was not reviewed.

This review read the CLI, the web server and UI entry files, the runtime (container launch and image build), the config manager, the challenge client and store, the solver, subagent and observer code, the built-in prompts and the skills `redis-webroot-rce`, `intranet-pentest`, `remote-cmd-execution`, `known-product-exploit`, `php-payload-builder`, `tch-headless-skill` and `recon`. The skill folders `payloads-everything` (391 files), `fuzz-dicts-skills` (198) and `pentest-fuzz-skill` (43) hold payload and wordlist files, including web shells, and were not opened. The compiled solver binary (`packages/core/src/runtime/assets/tch-agent-linux-x64`) is generated at build time and is not in the repository.

Paths written as `skills/builtin/...` or a bare skill folder name are under `packages/core/src/config/skills/builtin/`.

**Fragility** says what it takes to remove a signal: *code* means editing BreachWeave, *config* means a setting in `~/.tch-agent/config/settings.json` or a command-line option, *operator* means a choice made at run time, *code (prompt)* means text in a shipped prompt or skill that the model follows and may vary.

What someone who reaches an exposed console can do, read from the code and not tested: on `main`, everything without a login. They can read stored model API keys and the contest `agentToken` (`/api/config/providers`, `/api/config/host-settings`), start solver containers on the host network with a task of their choosing (`POST /api/runtime/solvers`), run shell commands in a running solver (`POST /api/runtime/solvers/<id>/command` with `{"type":"bash",...}`), change the solver image, environment and bind mounts for the next container (`POST /api/config/host-settings`, which the runtime reads into `docker run -v`), and make the host clone any git URL. On `pentest`, the same after registering an account, which is open by default.
