# What Shannon leaves behind

Shannon ([KeygraphHQ/shannon](https://github.com/KeygraphHQ/shannon), npm `@keygraph/shannon`, Docker Hub `keygraph/shannon`; repository created September 27, 2025; AGPL-3.0; 52,307 stars and 6,136 forks on November 26, 2026; latest release `v3.6.1`, November 20, 2026; reviewed at `3760d2f9`, November 25, 2026) is a TypeScript CLI from Keygraph that pentests a web application or API it has the source code for. Model-driven agents read the code, map the attack surface with a headless browser, analyse five vulnerability classes (injection, XSS, authentication, authorization, SSRF, plus a generalist class) and then try to exploit each finding against the running application. A scan runs as a Temporal workflow in a Docker worker container, and the result is a Markdown and PDF report. Keygraph sells hosted (Keygraph Pro) and self-hosted (Enterprise) editions built on it. Its benchmark write-up calls it Shannon Lite and reports 96.15% on a hint-free copy of the XBOW benchmarks ([KeygraphHQ/xbow-validation-benchmarks](https://github.com/KeygraphHQ/xbow-validation-benchmarks)). The npm package was first published March 18, 2026; the Docker Hub image had 91,146 pulls on November 26, 2026. File references are to the repository at `3760d2f9df9f3afa374a8eb2473adadfbf9ed991`.

**Fragility** says what it takes to remove a signal: *code* means editing Shannon, *config* means an environment variable or option, *operator* means a choice made at run time. *Code (prompt)* marks a string the prompts tell the model to use: removing it means editing Shannon, but the model may not follow it on every call.

## An exposed console

Shannon has no web interface of its own: the CLI and the worker open no listening socket (no HTTP server in `apps/`). The only console is the Temporal Web UI of the dev server it starts, published on `127.0.0.1:8233` with gRPC on `127.0.0.1:7233` (`docker-compose.yml:10-12`). The CLI points operators at `http://localhost:8233` (`apps/cli/src/scan/render.ts:87`). The UI has no login in dev mode and shows every scan: workflow type `pentestPipelineWorkflow`, workflow IDs `<target host>_shannon-<epoch ms>`, task queues `shannon-<8 hex>` and the inputs, which include the target URL.

A Temporal UI is reachable from outside only if someone changes the port mapping or forwards the port. Its page title and favicon are Temporal's own, shared with every Temporal deployment, so a Shodan search cannot tell a Shannon Temporal from any other, and this folder has no Shodan query. Suricata rule 3813010 sees the workflow list when the UI or its `/api/v1/namespaces/<ns>/workflows` API is read in cleartext. The plugin icons (`plugins/shannon/assets/icon.png`, mmh3 `-1784739300`, MD5 `6b323f2a1c1a31dbe1b5c517d66a36ff`; `logo.png`, mmh3 `-517921519`, MD5 `1bf2d81350bce8f1354ebac0689b08c9`) are marketplace assets, not served by Shannon.

## What has been seen in the wild

- No public report of Shannon used against a target without authorization was found on November 26, 2026, and no public detection rules for it.
- Keygraph published its own run logs and deliverables for 104 XBOW challenges (October 2025, an older version). They show the model choosing curl and its own user agents; those strings are not in the code and are not used as indicators here.

## What the code does not contain

No implant, C2, persistence or telemetry. The agents use a shell, a browser and the operator's credentials for the target, and the results stay in the workspace folder. The php2shell probe stops at the crash: the code says it never sends the follow-up request for code execution (`apps/cli/src/exp-php2shell/probe.ts:1-8`).
