# What Agentic Bug Hunter leaves behind

Agentic Bug Hunter ([awarexone/Agentic-Bug-Hunter](https://github.com/awarexone/Agentic-Bug-Hunter); created March 8, 2026; MIT; 6,072 stars and 1,114 forks on November 26, 2026; not archived; Python, shell, one HTML page and one JavaScript file) is a bug bounty toolkit by AwareXone. Its `go.mod` says the repository was earlier published as `github.com/shuvonsec/claude-bug-bounty` (`go.mod:3-8`). It ships as a Claude Code plugin and as skills, commands and agents for Codex, OpenCode, Gemini/Antigravity and pi, plus a standalone CLI with its own ReAct agent, about a hundred Python and shell scripts, an MCP server and a local web dashboard. The package is on PyPI as `agentic-bug-hunter` (6.0.0 to 6.0.2; the repository says 6.0.1). There is no Docker image and no hosted service in the code. Releases v1.0.0 (March 13, 2026) to v6.0.0 (August 21, 2026). Reviewed at `82f4512e` (`82f4512ec432765297c36e6b3ef7dc3fe5a58be2`, November 12, 2026), the head of `main` on November 26, 2026. File references are to that commit. The scripts moved from `tools/` to `bughunter/tools/` on September 22, 2026; older installs use the old paths.

**Fragility** says what it takes to remove a signal: *code* means editing the toolkit, *config* means an environment variable or setting, *operator* means a choice made at run time. *Code (prompt)* marks a string that is an example in a skill, command or agent prompt: the model can change it on any run, so treat it as likely, not certain.

## An exposed Hunt Dashboard

The dashboard is the only HTTP listener the toolkit opens for longer than a login. It binds `127.0.0.1:8777` by default. It checks the `Host` header against an allow list before it reads anything: the loopback names always, the bind host when it is a specific address, and each `--allow-host`. Bound to `0.0.0.0` or `::`, the bind host is not added, so a scanner that connects by IP gets the 403 below. Bound to a specific public IP, a scanner that uses that IP in `Host` gets the full page. Binding to anything other than loopback prints `exposes this UNAUTHENTICATED dashboard to your network`. Behind a reverse proxy with `--allow-host <name>`, it answers on that name.

Where model traffic is inspected, the autonomous agent's system prompt starts `You are an elite autonomous bug bounty hunter operating within an authorized bug bounty program or VAPT engagement.` with `CORE RULES:` and tool names `run_recon`, `read_recon_summary`, `run_cms_exploit`, `run_rce_scan`, `run_sqlmap_targeted`, `run_jwt_audit`, `update_working_memory`, `finish` (`bughunter/agent.py:1401-1417`). ## What has been seen in the wild

- No vendor or CERT report of Agentic Bug Hunter used in an intrusion was found (November 26, 2026).
- No public detection rules for it were found.

## What the code does not contain

No implant, C2, persistence or lateral movement code, and nothing that runs on a target host. The credential chain (company wordlist, HIBP ranking, spray) is the part most likely to cause harm: it can lock accounts, and the orchestrator itself warns that most programs forbid it. The interactive host-name confirmation stops an agent from starting a spray alone, but a person can run it directly. Scope checks exist (`scope_checker.py`, `safe_http.py` refuses redirects to private and metadata addresses) but the scope is whatever the operator declares.

## Not verified, and inferred

- Nothing was run. Command lines, the `Server` header and request shapes are read from the code or inferred from Python, curl and urllib defaults.
- The PyPI release 6.0.2 is newer than the repository's 6.0.1 and was not inspected.
- Strings in skills and commands (`Code (prompt)`) were not checked against real assistant sessions.
- The OOB payloads are printed for the operator or the model to place; which ones reach a target depends on them.
- The SAML signature-stripping request is sent only when an earlier step found a `saml/acs` or `saml/login` endpoint; a code comment says the metadata leg had never reached the network before a recent fix (`vuln_scanner.sh:547-550`).
