# What RedAI leaves behind

RedAI ([kpolley/redai](https://github.com/kpolley/redai); repository created April 13, 2026; MIT; 356 stars and 36 forks on November 26, 2026; not archived; npm package `@kpolley/redai`, versions 0.1.0 to 0.1.3, the last published April 17, 2026; reviewed at `3ba2a98f` (`3ba2a98fb70e0855a28f97951af82ece9ecfe633`), April 26, 2026, the last commit) is a TypeScript terminal application for Bun, built with Ink and React. It asks Claude Code (through the Claude Agent SDK) or Codex (through the Codex SDK) to threat-model a source directory, rank its files, scan them in small units and merge the findings. Validator agents then try to confirm each finding against a running copy of the application in a prepared environment: a Chrome profile driven by the third-party `agent-browser` CLI, or a cloned iOS Simulator. It writes Markdown, JSON and HTML reports. File references are to the repository at `3ba2a98f`.

**Fragility** says what it takes to remove a signal: *code* means editing RedAI, *config* means an environment variable or setting, *operator* means a choice made at run time. *Code (prompt)* marks something a system prompt tells the model to do: removing it means editing RedAI, but the model may not follow it on every run, so treat it as likely, not certain. *Upstream* marks behavior of a library or tool RedAI drives (Claude Code, Codex, agent-browser), not of RedAI's own code.

## Exposure

None. RedAI has no web UI, API server or listener of its own; its output is files on disk. The agent-browser dashboard on `localhost:4848` that RedAI could open is agent-browser's, and the call to open it is dead code at `3ba2a98f`. There is no favicon, title or banner to search for, so this folder adds no Shodan queries.
