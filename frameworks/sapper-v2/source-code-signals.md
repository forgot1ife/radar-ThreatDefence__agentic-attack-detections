# What sapper-v2 leaves behind

sapper-v2 ([N1nEmAn/sapper-v2](https://github.com/N1nEmAn/sapper-v2); repository created October 30, 2026; one release, `v18-champion` at `240e4f88`, November 1, 2026; MIT; Python and shell; 2,642 stars and 1,282 forks on November 26, 2026; not archived; reviewed at `7b75e6f1` (`7b75e6f1f5d5b4ae0c55878b0dd0994d9b08f1fb`), November 11, 2026, the latest commit) is a kit that makes several sessions of a coding assistant work together on penetration-testing contest targets. Its author entered it in the Tencent Cloud intelligent attack-defense contest (TSecBench) qualifier. It has three parts: a Python CLI, `sapper`, that keeps a shared "engagement graph" of facts and intents as JSON files on disk; shell scripts that start Claude Code (and optionally Codex) sessions in tmux windows, type missions into them and restart them when they die; and a Kali Docker image built for the contest platform. The agents themselves are Claude Code (`@anthropic-ai/claude-code`, installed in the image) pointed at a Zhipu GLM or DeepSeek endpoint that speaks the Anthropic API. There is no PyPI or npm package, no published Docker image and no hosted service. File references are to the repository at `7b75e6f1`.

**Fragility** says what it takes to remove a signal: *code* means editing sapper-v2, *config* means an environment variable or setting, *operator* means a choice made at run time. *Code (prompt)* marks text the scripts type into a model session: removing it means editing sapper-v2, and the model then acts on it in its own words.

## Signals on the target side

sapper-v2 adds nothing of its own to traffic against a target. The agents run the Kali tools in the image, with their default user agents and options, from several Claude Code sessions in parallel.

## Exposure: the board

The only web interface is the board started by `sapper view --serve`. It binds to loopback by default; an exposed board means the operator passed `--host 0.0.0.0` (or a public address). It has no login, so an exposed board shows the graph of an engagement in progress or a past one: targets, services, credentials, vulnerabilities and flags recorded as facts.

## What could not be checked

- The design article the README links (WeChat) was not read. Nothing in the code implements the "taggant" marking the README proposes (`README.md:262-296`): there is no such marker at `7b75e6f1`.
- How the four exposed boards were started (port 2333 is not a default) is not known.
- `docker/nuclei.zip` is a nuclei release binary shipped in the repository; its version was not checked.
